# Мультимодальный просмотр фото на компактной VLM (ImageHub)

Работа выполнена в рамках проекта по дисциплине «Программные средства для задач искусственного интеллекта».

Локальный сервис для работы с изображениями: каталог, OCR с формулами и таблицами, описание сцены, лица, поиск, вопросы к картинке и ML-эксперименты.
Все модели не больше 3 млрд параметров. Данные не покидают ваш компьютер: сервис по умолчанию слушает только `127.0.0.1`.
Тяжёлая обработка (индексация, чат) идёт на GPU, поиск и просмотр работают на CPU.

## Возможности

- **Импорт.** Папки (с быстрой проверкой новых файлов и слежением), отдельные файлы, перетаскивание и вставка из буфера обмена. Форматы: jpg, png, webp, gif, tif (в том числе многокадровые), bmp, heic, avif.
- **Текст.** Дешёвый детектор текста и языка, затем OCR с формулами LaTeX и таблицами Markdown, правка опечаток. Переключатель «Отрендеренный / Исходный Markdown / До правки».
- **Сцена.** Описание на русском и английском (переключатель в панели), объекты с координатами, определение типа (фото, документ, график, чек и т. д.) и события, теги и категории.
- **Лица.** Глобальная база людей. Новые лица получают имя `person_N`, а разметка идёт в чате: рамка подсвечивается, сервис предлагает варианты, вы отвечаете именем или «да».
- **Поиск.** По тексту, по картинке и по их смеси с весом. Гибридный: эмбеддинги изображений, эмбеддинги описаний и BM25 по описанию и OCR. Запрос можно писать на русском или английском.
- **Чат.** Вопросы к выбранной картинке (Qwen3-VL-2B), ответ выводится потоком и отображается как Markdown с формулами. У каждой картинки свой чат.
- **Эксперименты.** Графики метрик распознаются и разбираются на ряды данных, максимум и плато считаются кодом. Первый эксперимент создаётся автоматически по дате первого графика, остальные создаёт пользователь.
- **Просмотр.** Лупа, масштаб, поворот, рамки, стрелки, подписи, кадрирование (всегда новой копией, оригинал не меняется), сравнение двух изображений, отмена и возврат (Ctrl+Z, Ctrl+Y).
- **Каталог.** Коллекции, категории (несколько на картинку), избранное, сортировка, фильтры по типу и дате, дубликаты, сводки.
- **Экспорт.** Конвертация в любой формат, склейка выделенных картинок в сетку N×M.

## Требования

| | Минимум | Рекомендуется |
|---|---|---|
| ОС | Windows 10/11 или Linux | то же |
| Python | 3.11 (в Docker 3.12) | 3.12 или 3.13 |
| Видеокарта | не нужна (режим CPU очень медленный) | NVIDIA от 8 ГБ VRAM |
| ОЗУ | 8 ГБ | 16 ГБ |
| Диск | 20 ГБ под веса | SSD |

Разработка и проверка шли на RTX 5060 (8 ГБ) и 32 ГБ ОЗУ. Пик использования ОЗУ сервисом около 1 ГБ, видеопамяти до 6,5 ГБ: модели загружаются по очереди, одновременно в памяти одна группа.

## Быстрый старт

```powershell
git clone <адрес репозитория> ImageHub
cd ImageHub
python -m venv .venv
.\.venv\Scripts\Activate.ps1            # Linux: source .venv/bin/activate

# 1) PyTorch под вашу видеокарту (RTX 50xx требует cu128 или новее; без видеокарты: cpu)
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128
# 2) сам сервис
pip install -e .

# 3) веса моделей (около 15 ГБ, скачиваются один раз в ./weights)
imagehub models --download
imagehub models                          # проверить, какие модели на месте

# 4) запуск
imagehub serve                           # http://127.0.0.1:8765
```

То же через `uv`: `uv sync --extra cu128` (также `cu126` и `cpu`), затем `uv run imagehub serve`.

Варианты PyTorch: `cu126` подходит для карт от Pascal до Ada, `cu128` нужен для Blackwell (RTX 50xx), `cpu` работает без видеокарты.

## Docker

Образ только для CPU, видеокарта и CUDA не нужны. Он основан на `python:3.12-slim` и включает системные библиотеки, PyTorch для процессора и пакет `imagehub`. Веса и данные в образ не входят и подключаются томами, поэтому образ можно пересобирать, не скачивая модели заново. На CPU обработка заметно медленнее, чем на GPU: для большой библиотеки используйте установку без Docker с видеокартой.

```bash
docker compose up --build                                 # сборка и запуск
docker compose run --rm imagehub models --download       # скачать веса один раз в ./weights
```

Тома (пути на хосте меняются переменными окружения):

| Внутри контейнера | На хосте по умолчанию | Переменная | Что хранится |
|---|---|---|---|
| `/weights` | `./weights` | `IMAGEHUB_WEIGHTS` | веса моделей |
| `/data` | `./data` | `IMAGEHUB_DATA` | база SQLite, миниатюры, копии |
| `/photos` | `./photos` (только чтение) | `IMAGEHUB_PHOTOS` | ваши фотографии |

В интерфейсе папку для импорта вводите как путь внутри контейнера, например `/photos`. Интерфейс открывается на http://127.0.0.1:8765. Вставки из буфера сохраняются в `/data/pictures`.

## Первый запуск: как пользоваться

1. Откройте http://127.0.0.1:8765. Слева кнопка добавления папки открывает обзор каталогов сервера. Выберите папку, и сервис сразу покажет миниатюры, а обработка пойдёт в фоне.
2. Индикатор очереди вверху показывает стадию и прогресс. Очередь можно поставить на паузу. Открытая сейчас картинка обрабатывается первой, вставка из буфера тоже.
3. **Вставка.** `Ctrl+V` в окне сохраняет картинку в `Изображения\ImageHub\clipboard` и обрабатывает её вне очереди. Если фокус в строке поиска, картинка станет образцом для поиска. Массового удаления вставок нет, удалять можно только выбранные.
4. **Поиск.** Строка сверху. Введите слова на русском или английском, добавьте картинку (перетаскиванием или `Ctrl+V` в поиске) и регулируйте вес текста ползунком. В контекстном меню картинки есть «Найти похожие».
5. **Правая панель.** Вкладки «Описание», «Текст», «Лица», «Чат», «Файл». В описании переключатель языка, в тексте переключатель рендера, во вкладке «Файл» путь и размеры.
6. **Лица.** Вкладка «Лица» показывает найденные лица с рамками. Разметка запускает диалог: лицо показывается крупно, предлагаются варианты (известные люди, роли вроде «прохожий» или «студент»), вы отвечаете и переходите к следующему.
7. **Графики.** Вставьте график из буфера. Он получит тип «график», будет отнесён к эксперименту, а на панели «Эксперименты» слева появятся максимум и плато по данным.
8. **Правка.** В просмотре включите инструменты рамки, стрелки, подписи или выделения. «Разметка в копию» сохраняет картинку с вашими пометками отдельным файлом, оригинал остаётся нетронутым.
9. **Контекстное меню** (правый клик): открыть, избранное, категории, коллекции, эксперимент, склейка N×M при выборе нескольких, экспорт, копирование самого изображения или пути, переименование, повторная обработка, удаление.

Проверка новых файлов запускается из «Инструментов». Быстрая проверка сравнивает время изменения каталогов, глубокая сверяет каждый файл. Слежение за папками работает постоянно, пока сервис запущен.

## Модели

Все модели скачиваются командой `imagehub models --download` с Hugging Face.

| Задача | Модель | Размер |
|---|---|---|
| Эмбеддинги, тип и событие, поиск | SigLIP2 base (`google/siglip2-base-patch16-256`) | 0,4 ГБ |
| Детектор текста и языка (CPU) | PP-OCRv5 mobile det и eslav rec, ONNX | ~13 МБ |
| Макет страницы (CPU) | DocLayout-YOLO, ONNX | 75 МБ |
| OCR: текст и формулы | GLM-OCR 0.9B | 2,7 ГБ |
| OCR: таблицы | PaddleOCR-VL 0.9B | 1,9 ГБ |
| Описание, объекты, регионы | Florence-2-large | 1,5 ГБ |
| Чат, разбор графиков, правка опечаток OCR, перевод описаний | Qwen3-VL-2B-Instruct | 4,3 ГБ |
| Эмбеддинги описаний и запросов | multilingual-e5-small | 0,5 ГБ |
| Лица (CPU) | InsightFace buffalo_l (SCRFD и ArcFace) | ~330 МБ |

Папка `model_lab/` содержит стенд, на котором модели сравнивались между собой (скрипты и реестр, без весов и образцов).

## Настройки

Переменные окружения с префиксом `IMAGEHUB_`:

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `DATA_DIR` | `./data` | база SQLite, миниатюры, производные файлы |
| `WEIGHTS_DIR` | `./weights` | веса моделей |
| `PICTURES_DIR` | `~/Pictures/ImageHub` | сюда сохраняются вставки и загрузки |
| `DEVICE` | `auto` | `cuda` или `cpu` |
| `OCR_FIX` | `true` | правка опечаток после OCR |
| `HOST`, `PORT` | `127.0.0.1`, `8765` | адрес сервиса |

Команды: `imagehub serve [--host --port]`, `imagehub scan <папка>` (добавить и просканировать без интерфейса), `imagehub models [--download] [--only id,id]`.

## Горячие клавиши

В каталоге: `/` поиск, `Ctrl+V` вставка, `Ctrl+A` выделить всё, `Ctrl+C` копировать изображение, `F` избранное, `F2` переименовать, `Del` удалить, `Enter` открыть, стрелки перемещают по сетке.

В просмотре: `←` `→` листание, `+` `-` масштаб, `0` по размеру, `1` 100%, `R` поворот, `L` лупа, `C` сравнение, `Ctrl+Z` отменить, `Ctrl+Y` или `Ctrl+Shift+Z` вернуть, `Ctrl+C` копировать изображение, `Esc` выход.

## Темы оформления

Тема выбирается в меню интерфейса или параметром адреса и запоминается в браузере: `/?theme=ocean`, `forest`, `sand`, `rose`, `graphite`, `midnight`, `nord`, `violet`. Галерея с предпросмотром: `/themes`.

## HTTP API

Интерфейс не содержит бизнес-логики, всё идёт через API (`/api`), документация OpenAPI на `/docs`. Основные группы: `/api/images` (список, карточка, файл, миниатюра), `/api/search`, `/api/import/*` (папка, пути, загрузка), `/api/queue`, лица и люди, `/api/chat` (потоковый ответ), `/api/experiments`, `/api/collections` и `/api/categories`, `/api/merge` и `/api/export`.

## Как это устроено

```
src/imagehub/
  config.py scanner.py watcher.py db.py imaging.py   каталог, быстрая проверка файлов, SQLite (WAL) и FTS5
  pipeline.py                                         фоновая обработка волнами по 16 картинок, по стадиям
  search.py queries.py people.py                      гибридный поиск (RRF), фильтры, база лиц
  ml/                                                 адаптеры моделей и менеджер видеопамяти
  api/                                                FastAPI: library, meta, faces, chat, tools
  web/static/                                         интерфейс без сборки (ES-модули, KaTeX, markdown-it)
tests/                                                pytest и сценарии Playwright для интерфейса
model_lab/                                            стенд сравнения моделей
```

- Обработка идёт волнами: одна группа моделей находится в VRAM, через неё проходят все картинки волны, затем загружается следующая. Вопросы пользователя в чате имеют приоритет над очередью.
- Поиск объединяет три списка (SigLIP2, e5 по описаниям, BM25) через RRF. Описания индексируются на английском и на русском, поэтому запрос работает на любом из двух языков.
- Рамки объектов и лиц хранятся в координатах оригинала. Версия пайплайна пишется в базу, чтобы переобрабатывать выборочно.
- Вставки и единичные файлы обрабатываются без перевода описания, перевод доделывается в фоне.
